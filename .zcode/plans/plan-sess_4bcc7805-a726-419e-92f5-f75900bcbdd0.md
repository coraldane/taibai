## 问题诊断

`bind_params`(`src/sql/execution/prepared.rs:139`)与同文件的 `count_placeholders`、`has_placeholders` 出现逻辑不一致:

- `count_placeholders` 和 `has_placeholders` **已经覆盖**了 `Select` 的 group_by / having / order_by / limit / offset 五个字段
- 但 `bind_params`(真正执行占位符→Literal 替换的函数)对 `Statement::Select` 只写了 `where_clause => Some(expr)` 一个分支,**这五个字段全部漏掉**

这导致客户端走 Prepared Statement 协议时,`SELECT ... LIMIT ? OFFSET ?`、`GROUP BY ?`、`HAVING ? > ?`、`ORDER BY ?` 这类写法的占位符永远不会被替换,后续 planner 的 `eval_const_usize` 会因遇到 `Expr::Placeholder` 而报错 "expected integer literal for LIMIT/OFFSET"。

此外 `count_placeholders`/`has_placeholders` 也遗漏了 `Statement::Union`(它在 `ast.rs:186-193` 同样带 order_by / limit / offset 三个 Expr 字段)。

## 改造方案

**核心原则**:让 `bind_params` / `count_placeholders` / `has_placeholders` 三个函数对 Statement 各字段的覆盖范围保持完全一致,杜绝"统计了却不替换"这种内部不一致。

### 1. 修改 `bind_params`(`src/sql/execution/prepared.rs:139-182`)

把 `Statement::Select` 分支由只匹配 `where_clause` 改为完整解构所有含 Expr 的字段,对 group_by / having / order_by / limit / offset 统一调用 `substitute_placeholders`:

```rust
Statement::Select {
    where_clause,
    group_by,
    having,
    order_by,
    limit,
    offset,
    ..
} => {
    if let Some(expr) = where_clause {
        substitute_placeholders(expr, params)?;
    }
    for e in group_by.iter_mut() {
        substitute_placeholders(e, params)?;
    }
    if let Some(expr) = having {
        substitute_placeholders(expr, params)?;
    }
    for item in order_by.iter_mut() {
        substitute_placeholders(&mut item.expr, params)?;
    }
    if let Some(expr) = limit {
        substitute_placeholders(expr, params)?;
    }
    if let Some(expr) = offset {
        substitute_placeholders(expr, params)?;
    }
}
```

注意:当前代码有 `where_clause: Some(ref mut expr)` 和 `where_clause: None` 两个分支(后者无 where 也要跑占位符?实际上 None 分支只处理了 Update 的 assignments)。改造后用一个 `if let Some` 统一处理,语义等价且更清晰。

### 2. 新增 `Statement::Union` 分支到三个函数

`Union` 在 `ast.rs:186-193` 也带 `order_by: Vec<OrderByItem>`、`limit: Option<Expr>`、`offset: Option<Expr>`。给 `bind_params` / `count_placeholders` / `has_placeholders` 三个函数都补上 Union 分支(保持三者一致)。

### 3. 验证 planner 消费路径(只读确认,不改)

确认替换后的 Literal 能顺利通过:
- `eval_const_usize`(`planner/types.rs:237`)只接受 `Literal(Int64/Int32)` — 替换后正好满足
- group_by / having / order_by 走 `plan_expr` 正常求值,Literal 本就是合法表达式

无需改 planner。

### 4. 加测试(`src/sql/execution/prepared.rs` 末尾新增 `#[cfg(test)] mod tests`)

为每个新支持占位符的场景加单元测试,模式:parse SQL → `bind_params(stmt, &[params])` → 断言对应字段的 Expr 已从 `Placeholder` 变为 `Literal(预期值)`。覆盖:
- `SELECT * FROM t LIMIT ? OFFSET ?` → 断言 limit/offset 为 Literal
- `SELECT a, count(*) FROM t GROUP BY ? HAVING count(*) > ?` → 断言 group_by[0] / having
- `SELECT * FROM t ORDER BY ?` → 断言 order_by[0].expr
- `SELECT * FROM t WHERE id = ?` → 回归测试(where 原本就支持)
- `SELECT * FROM t UNION SELECT * FROM t2 ORDER BY ? LIMIT ?` → 断言 Union 分支
- 参数数量不足时的越界报错(`bind_params` 返回 Err)

测试用 `Parser::parse` 直接拿到 `Statement`,不依赖网络层,保持单元测试轻量。

## 影响范围

- 只改一个文件:`src/sql/execution/prepared.rs`
- 不改 AST、parser、planner、executor、网络协议层
- 完全向后兼容:原本就支持占位符的字段(where/values/assignments)行为不变;原本"统计了却不替换"的 bug 字段现在是"统计并正确替换"
- 普通非 prepared 查询路径(`engine.rs:execute`)不经过 `bind_params`,SQL 里若含 `?` 仍会按原逻辑报错——这是预期行为,占位符本就只应走 Prepared Statement
