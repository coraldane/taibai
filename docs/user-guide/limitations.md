# 项目状态与限制

Taibai 是用于分析型数据库能力探索、功能验证和性能实验的 Rust 列式数据库服务端。当前版本为 `0.x`，尚未声明生产就绪。

## 当前适用场景

- 学习和研究列式数据库内部实现。
- 验证 SQL、存储、协议和查询优化方案。
- 在可丢弃或已有独立备份的数据上进行功能测试。
- 开展可重复、明确记录环境的性能实验。

## 不建议的场景

- 将 Taibai 作为唯一数据副本。
- 未经额外安全评估直接暴露到公网。
- 依赖稳定的数据文件格式、网络协议或 SQL 兼容性。
- 需要明确高可用、灾难恢复、审计或长期支持承诺的生产系统。

## 稳定性与兼容性

- `0.x` 版本可能修改配置项、命令行参数、SQL 行为和公共 Rust API。
- 自定义网络协议和 segment 文件格式尚未承诺跨版本兼容。
- 升级前应备份数据，并在隔离环境验证读取、写入和恢复流程。
- SQL 语法是项目自有实现，不代表完整兼容 MySQL、PostgreSQL、ClickHouse 或其他数据库。
- 文档列出的能力可能仍在持续优化，应以当前版本测试结果为准。

## 功能边界

项目包含事务、权限、分区、TTL、索引、Join、子查询、窗口函数和查询优化等实现，但不同功能的覆盖深度和压力验证程度并不相同。使用具体能力前，应运行对应测试并针对业务数据补充端到端验证。

事务隔离语义、并发冲突行为、崩溃恢复边界和跨版本恢复能力尚未形成稳定的外部兼容承诺。

## 安全边界

- 默认 `root/taibai` 凭据只用于本地开发。
- TLS 默认关闭。
- 使用者负责网络隔离、凭据管理、文件权限、备份和日志脱敏。
- 发现漏洞时请遵循仓库根目录的 [安全策略](../../SECURITY.md)。

## 性能数据

仓库中的性能数据只代表文档所述环境和测试方法，不构成对其他硬件、数据分布或负载的性能承诺。性能对比应记录版本、配置、硬件、数据集、预热方式和完整命令。

## 发布前检查

将 Taibai 用于非本地环境前，至少应完成：

1. 修改默认凭据并限制网络访问。
2. 启用和验证 TLS。
3. 使用独立持久化目录并设置最小文件权限。
4. 建立备份和恢复演练。
5. 对实际 SQL、并发量和数据规模执行压力测试。
6. 验证升级和回滚流程。
7. 评估当前版本的已知问题和变更记录。
